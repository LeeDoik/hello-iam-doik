# How this site was built

이 사이트는 Claude Code와 함께 만들었다. 아래는 실제로 거친 절차와, 그 안에서 사람이 결정한 것과 AI가 한 것의 구분이다. 레포에 없는 것은 없다고 적는다.

## 절차

1. **브레인스토밍.** 목표(웹·AI 취업용 포트폴리오이자 "왜"를 배우는 학습 프로젝트)와 제약(완전 정적, 한/영, GitHub 레포가 콘텐츠 원천, Vercel Hobby, 히어로 한 곳에만 3D)을 질문과 답으로 확정했다. 확정된 제약 표는 스펙 §1에 있다.
2. **설계안 3개와 심사.** AI가 설계안 3개를 만들고, 멘토 관점과 국내 시니어 FE 면접관 관점의 두 심사가 평가했다. "Fewest Moving Parts(Astro 7)" 안이 선정되었고, 심사에서 나온 아이디어 일부를 이식했다. 최종 선택은 내가 했다.
3. **스펙.** 선정안을 `docs/superpowers/specs/2026-09-02-portfolio-site-design.md`로 문서화했다. 스택 표의 각 행("무엇 / 왜 / 기각한 대안")이 ADR의 초안이 되었다.
4. **계획 4개.** `docs/superpowers/plans/`에 1차 기반, 2차 자산 파이프라인과 히어로 3D, 3차 실제 콘텐츠, 4차 마감 계획을 순서대로 썼다. 각 계획은 태스크 단위로 쪼개져 있다. 1차~3차 계획은 머리에 'Global Constraints' 절을 두었고, 3차·4차 계획은 구현자가 유일한 원천으로 쓸 '사실' 목록을 두었다(4차는 그 목록에 "바꾸지 말 것"이라고 표시했다).
5. **태스크별 구현과 독립 검토.** 태스크마다 서브에이전트(별도 Claude Code 세션)가 브리프(태스크 지시문)를 받아 구현하고, 다른 에이전트가 diff를 검토했다. 검토에서 나온 지적은 같은 태스크 안에서 고쳤다. 브리프, 보고서, 검토 diff는 `.superpowers/sdd/`의 작업 원장(태스크별 진행 기록, `progress.md` 포함)에 쌓였는데, 이 폴더는 `.gitignore`에 있어 레포에는 없다. 레포에 남은 것은 커밋과 ADR이다.
6. **디자인 패스.** 3차 뒤에 별도 워크플로우로 진행했다. 순서는 현재 상태 감사 → 시안 3개 → 심사 → 구현 → 다관점 QA였고, 결과는 `design/dark-tokens` 브랜치의 커밋들(다크 우선 토큰과 타입 스케일, 간격, 탭 타겟, 히어로 폴백 보강)로 main에 병합되었다. 중간 산출물은 레포에 없다.
7. **검증과 병합.** 로컬에서 `pnpm check`, `lint`, `test`, `build`, `test:build`, `e2e`를 돌리고, PR마다 CI(`ci` 워크플로우의 check → lint → test → build → test:build → Lighthouse CI → e2e → gitleaks)가 게이트였고, `content/**`를 건드리는 PR에는 `links` 워크플로우가 추가로 돌았다(ADR-0007). 커밋은 검토 후 컨트롤러 세션(내가 직접 대화하는 메인 세션)이 만들었다. git author는 나와 dependabot이지만, 컨트롤러 세션이 만든 커밋에는 `Co-Authored-By: Claude` 트레일러가 붙어 있어 git 로그에서 구분된다.

## 사람이 결정한 것

- 요구사항과 제약, 그리고 설계안 3개 중 무엇을 고를지.
- 테마를 다크 우선으로 할지. 어떤 프로젝트를 어디까지 공개할지(PIXELARIOUS 레포는 비공개 유지, 태엽새는 재배포 전까지 라이브 링크 없음).
- 프로젝트 페이지의 사실 표 검토. 수치, 측정 방법, 근거 링크가 실제 보고서·로그·커밋과 맞는지.
- 브랜치 병합 시점과 무엇을 다음 계획으로 미룰지.
- ADR의 "What I learned" 절. 이 절은 사람이 쓰는 것을 관행으로 삼았다. 초안이 AI에서 나온 문장이라도, 내가 이해해 다시 쓴 뒤에만 남긴다.

## AI가 한 것

- 조사, 설계안 초안, 스펙과 계획 초안.
- 코드 초안과 테스트 초안, 문서 초안(이 문서 포함).
- 스크린샷 캡처 스크립트 실행과 sidecar 기록, ADR 개정문(Amendment) 초안.
- 다른 에이전트가 쓴 코드의 검토.

## 숨기지 않는 것

- `content/experience.yaml`에는 `[채워 주세요]` 자리표시가 5곳 남아 있다. 화면에는 나오지 않는다(`src/lib/placeholders.ts`가 조직명이 자리표시인 항목은 통째로, 실제 항목 안의 자리표시 불릿은 그 불릿만 걸러낸다). 그래서 채우기 전까지 학력 항목과 수강 과목 항목이 랜딩과 `/resume/`에서 비어 보인다. 학교·전공, 학위, 학교 항목의 불릿 한 줄(`experience.yaml` 9행), 수상 결과, 수강 과목처럼 내가 직접 채워야 하는 항목이다. 공유 전 차단 항목으로 `docs/launch-checklist.md`에 적어 두었다.
- 초기 ADR(0004, 0005, 0009)의 "Try it" 예시는 당시의 샘플 프로젝트 slug를 쓴다. 본문은 고치지 않고 끝에 개정문을 붙여 현재 slug를 안내한다.
- 태엽새는 Railway 재배포 전이라 `status: archived`이고 라이브 링크가 없다. 재배포 후 `pnpm capture heart-of-steel`로 스크린샷을 다시 찍고 상태를 바꾼다.
- Aetheria Online의 동접·지연 수치는 localhost 측정치이며, 페이지에 그렇게 표기했다.
